# Applied review changes — 2026-08-26

Independent reviews: `reviews/claude.md`, `reviews/crush.md`.
Architecture not reopened (AuthZEN facade over OpenTDF v2; CWT stays). No commit.

## Verified in tree and applied

1. **Device `sub` ≠ PE `sub` (both reviewers).** Defined `subject_id_bind(s)` that strips a single leading `arkavo:` only (not `apple:` / `client:`). PEP 401 and facade deny-closed use the bind, not raw equality. `$token.sub` documents minted formats: bare UUID for DeviceCheck and WebAuthn auth/registration; `arkavo:{uuid}` for OIDC access; `client:{id}` for service CWTs. Examples now show PE `arkavo:550e…` binding to device `550e…`. PR 3b adds a mismatched-prefix fixture. PR 5 MUST replace `catalog_api.rs` `claims.sub != pe.sub`.

2. **Empty evaluations citation (crush #2).** Re-cited AuthZEN §7.1.1 (required subject/action/resource). §7.1 is only the backwards-compatible single-evaluation behavior.

3. **"Registered" subject type (both).** Dropped "Registered". `identity` is the COAZ-MCP / profile value; AuthZEN 1.0 has no subject-type registry.

4. **Profile labels (crush #4, claude #10).** Labeled `evaluation_id`, `context.pep.fulfillable_obligation_fqns`, and `context.obligations.required` as **(profile)** free-form `context` per AuthZEN §5.5.1. Obligations and `evaluation_id` are per-evaluation for `/evaluations` and top-level for `/evaluation`.

5. **entity.proto vs authorization.proto (crush #5).** `entities.size() > 0` is on `authorization.proto` `EntityIdentifier.entity_chain`, not `entity.proto`.

6. **MCP Bearer claim (crush #6).** User token is Bearer only on ERS `CreateEntityChainsFromTokens`; `GetDecision*` via `make_connect_request` has no Authorization header.

7. **Missing REQUIRED device fields (crush #7).** Missing `sub`/`iss`/`aud`/`kid` → HTTP 400 malformed SARC. Present-but-wrong `aud`/`sub` → deny-closed.

8. **Environment allowlist (claude #7).** Replaced denylist with allowlist `{region}` plus optional `kind`; drop every other key. Device objects: allowlist `{sub,iss,aud,kid}` only.

9. **Tool FQNs / `attribute_value_fqns` (claude #6).** For `resource.type` in `{tool, mcp_server}` the facade MUST derive FQNs and MUST reject (400) PEP-supplied `attribute_value_fqns`. PEP-supplied FQNs remain only for `catalog_item` / `tdf` / `kas`. Added security-table row "Resource substitution". Observability logs evaluated FQNs or count/hash.

10. **Multi-aud (claude #5, #13).** Added `AUTHZEN_MCP_RESOURCE_ID` (RFC 8707 resource id of this MCP server). `tools/list` requires that value in `$token.aud` (string or array member) else mapping error. `context.agent` fallback: exactly one `aud` member that is neither `arkavo`, `arkavo:devicecheck`, nor `OIDC_PLATFORM_AUDIENCE`. Service CWT `aud` is `client_id` plus optional platform audience. Added a worked multi-aud example.

11. **MCP subject credential (claude #4, qualified).** There is no crate `arkavo-mcp-proxy`. Only in-tree caller of `authorize_mcp_tool` is `arkavo-mcp-claude/src/policy_bridge.rs` (`CLAUDE_CODE_SESSION_ACCESS_TOKEN` falling back to `ANTHROPIC_API_KEY`). Spec now requires an Arkavo CWT (`Authorization: Bearer` or a named env documented CWT-only); `ANTHROPIC_API_KEY` MUST NOT be a subject credential. PR 4 files include `policy_bridge.rs` and instruct: locate and update the MCP JSON-RPC dispatcher; do not assume `arkavo-mcp-proxy`. Inspected candidates: `arkavo-mcp-runtime` dispatches `execute_tool`/`list_tools` (not MCP `tools/call`/`tools/list`); `arkavo-mcp` is types; `arkavo-cli/src/mcp_client.rs` is a client. The swarmkit-apply tree has `arkavo-cli/src/commands/mcp.rs` which does dispatch `tools/list`/`tools/call`; that file is absent from `arkavo-edge`. Error codes remain `-32001` / `-32602` / `-32603`.

12. **PR 2b deps (claude #12).** Added `arkavo-rs/Cargo.toml` and `coset`.

13. **v1 obligations (claude #9).** Empty fulfillable list ⇒ platform DENYs resources with triggered obligations. Operators MUST confirm no production attribute value carries an obligation trigger before flipping catalog `protocol=authzen`. Shadow phase diffs this.

14. **Multi-device v1 policy effect (claude #8).** Kept as v1 wire + verification. Stated in Goals and Key Decision 25: v1 decisions are unaffected because device NPEs are `CATEGORY_ENVIRONMENT` and `skipEnvironmentEntities=true`. Named future: platform stops skipping, or a `kind`/`npe_type` claim distinguishes devices.

## OpenTDF charset (claude #1, #3) — fetched and treated as fact

Fetched `opentdf/platform` `main` on 2026-08-26. Confirmed `CreateAttributeValueRequest.value` and `CreateActionRequest.name` regex `^[a-zA-Z0-9](?:[a-zA-Z0-9_-]*[a-zA-Z0-9])?$` with lowercase normalization. Adopted as a profile MUST; PR 3 entry spike still confirms against the deployed platform.

- Alias table: `git_commit` not `git.commit`; dots map to underscores. In-tree `McpToolMapping::tool_to_resource` currently emits `git.commit` and MUST change in PR 4.
- `mcp_server` `resource.id` is a configured slug (`AUTHZEN_MCP_SERVER_SLUG` or slug form of `AUTHZEN_MCP_RESOURCE_ID`), not a percent-encoded URL. Deleted the uppercase-HEXDIG MUST and the encode-only-slash negative example (kept as a rejected alternative).
- AuthZEN action names may still be `tools/list` / `issue:cwt:authorization_code`; OpenTDF column is charset-safe (`tools_list`, `issue_cwt_authorization_code`). Facade MUST NOT pass through an unmapped action whose OpenTDF name would violate the charset (HTTP 400). Mapped action names are lowercased.
- Key Decisions 18 and 20 updated.
